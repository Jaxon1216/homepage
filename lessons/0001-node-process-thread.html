后端运行模型 · 01 / 建议 5 分钟

一个 Node 进程，
如何同时处理多个请求？

本课目标：能沿着一段代码指出线程在什么时候执行、什么时候等待。

1. 先划清边界

运行一次 node app.js，通常启动一个 Node 进程。进程内主线程执行启动代码，以及普通 JavaScript 回调；它一次执行一段 JS，并按执行流程调用不同的函数。线程不需要先“跑完整个文件”，也不会因每个请求复制一套代码。[Node 官方指南]

Node 进程
├── 主线程：启动代码、路由回调、await 后续 JS
└── 其他运行时线程：按需执行运行时分配的工作

一份程序定义多个函数 ──→ 按实际调用顺序逐段执行

“Node 单线程”通常是指默认主线程执行这段应用 JavaScript。整个进程可能有多个线程，实际线程数量由运行时、版本和使用的功能决定。

2. 看两次请求怎么穿插

示意代码：假设 query 是真正异步的数据库驱动操作，await 后面的代码仍由同一个 JS 主线程恢复执行。

app.get('/user', async (req, res) => {
  console.log('开始', req.query.id) // 主线程
  const user = await query(req.query.id)
  console.log('结束', req.query.id) // 主线程
  res.json(user)                   // 主线程
})
时间   主线程                         数据库
 1     A：打印开始，发出查询 ───────→ A 执行中
 2     A 在 await 处暂停
 3     B：打印开始，发出查询 ───────→ B 执行中
 4     B 在 await 处暂停              A 返回
 5     A：恢复、打印结束、返回响应    B 返回
 6     B：恢复、打印结束、返回响应

这是一种可能的时序；具体先后取决于请求到达、数据库完成和调度时间。等待期间记录了后续如何继续；不是一个线程蹲在那里等待 A。网络 I/O 可通过操作系统的非阻塞机制处理，不应说所有等待都交给了工作线程池。[事件循环]

如果 query 返回之前在主线程做了大量同步计算，或者 await 后面有耗时同步循环，主线程仍会被占住，其他 JS 回调就必须等。

请求 A 等待异步数据库响应时，主线程能否执行请求 B 的短小 JS 回调？
